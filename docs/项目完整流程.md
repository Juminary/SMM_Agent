## 一、系统启动

```
┌──────────────────────────────────────────────────────┐
│                    启动后端                           │
│  cd SMM_Agent/backend                                │
│  pip install -r requirements.txt                      │
│  python -m app.db.migrate        ← 建表 + 灌入初始JSON数据 │
│  python -m app.db.seed_data --reset  ← 生成500+物料/200+报价 │
│  python run.py                   ← FastAPI @ 8000端口  │
└──────────────────────┬───────────────────────────────┘
                       │
┌──────────────────────▼───────────────────────────────┐
│                    启动前端                           │

│  npm install                                         │
│  npm run dev                     ← Vite @ 5173端口   │
└──────────────────────────────────────────────────────┘
```

访问 `http://localhost:5173` → 看到 **Agent 工作台 Dashboard**

## 三、后端两阶段处理（核心流程）

请求到达 `POST /api/quotes/analyze` → `AgentOrchestrator.process_quote()`

```
┌─────────────────────────────────────────────────────────────────────┐
│                    LangGraph Agent 图执行                            │
│                                                                     │
│  START                                                              │
│    │                                                                │
│    ▼                                                                │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │ 第一阶段：体检 (确定性, 无LLM)                               │   │
│  │                                                              │   │
│  │  node_build_material                                         │   │
│  │    → 构造物料对象 {name, category, supplier, price, ...}     │   │
│  │    → 写入 execution_trace: "物料构造"                         │   │
│  │                                                              │   │
│  │  node_run_baseline (串行3项)                                  │   │
│  │                                                              │   │
│  │    ├── ① tool_predict_price_range                            │   │
│  │    │   → 层次贝叶斯模型 (PyMC MCMC) 预测 P10/P50/P90         │   │
│  │    │   → 失败降级: 分位数统计                                  │   │
│  │    │   → 写入 trace: "价格预测"                                │   │
│  │    │                                                          │   │
│  │    ├── ② tool_analyze_cost_structure                         │   │
│  │    │   → 行业基准反推5项成本 (原材料/加工/表面/包装/管理)    │   │
│  │    │   → 原材料项与市场参考价交叉验证                          │   │
│  │    │   → 写入 trace: "成本拆解"                                │   │
│  │    │                                                          │   │
│  │    └── ③ tool_match_similar_material                         │   │
│  │        → TF-IDF char n-gram 向量检索 Top-5 相似物料           │   │
│  │        → 可选升级: sentence-transformers 语义向量              │   │
│  │        → 写入 trace: "相似物料检索"                            │   │
│  │                                                              │   │
│  │  node_score_deviation                                        │   │
│  │    → 第一层: α×价格偏离 + β×成本偏离 + γ×市场偏离           │   │
│  │    → 第二层: 偏离度×0.6 + 外部偏离×0.4 (RAG校准)            │   │
│  │    → 输出: deviation_score 0~100 + severity_level             │   │
│  │    → 写入 trace: "偏离度评分"                                  │   │
│  │                                                              │   │
│  │  node_triage (分流节点, 无LLM)                                │   │
│  │    ┌───── score < 20 ────→ 快速通道 (自动通过)              │   │
│  │    ├── 20 ≤ score < 60 → 标准诊断 + 人工确认                 │   │
│  │    └── score ≥ 60 ──────→ 紧急诊断 + 强制确认                │   │
│  │                                                              │   │
│  │  写入 trace: "分流决策"                                       │   │
│  └──────────────────────────┬──────────────────────────────────┘   │
│                             │                                       │
│              ┌──────────────┴──────────────┐                       │
│              ▼                              ▼                       │
│  ┌─────────────────────┐    ┌─────────────────────────────┐        │
│  │ 快速通道             │    │ 第二阶段: Agent诊断 (LLM)    │        │
│  │                     │    │                             │        │
│  │ node_fast_pass      │    │ node_start_diagnosis        │        │
│  │   → 生成"直接通过"   │    │   → 分析3个偏离分的模式       │        │
│  │   → 方案置信度95%    │    │   → 生成根因假设 H1~H4      │        │
│  │   → 不调LLM         │    │   → 写入 trace: "诊断启动"   │        │
│  │   → 不等人           │    │                             │        │
│  │                     │    │ ════════════════════════════ │        │
│  │ 写入trace: "快速通道"│    │ ReAct 循环 (最多5轮):        │        │
│  └─────────┬───────────┘    │                             │        │
│            │                │ node_agent_router            │        │
│            ▼                │   → Kimi K2.5 LLM 自主决策   │        │
│          END                │   → 选择1-2个诊断工具         │        │
│                             │   → function calling 参数填充 │        │
│                             │   → 写入 trace: "Agent决策"   │        │
│                             │         + decision_log       │        │
│                             │         ↕                    │        │
│                             │ node_execute_diagnostic_tool │        │
│                             │   → 执行LLM选择的工具        │        │
│                             │   → 结果写回state对应字段    │        │
│                             │   → 写入 trace: "诊断工具:XX" │        │
│                             │                             │        │
│                             │ 可用诊断工具 (7个):           │        │
│                             │  1. tool_get_supplier_profile│        │
│                             │  2. tool_compare_peer_price   │        │
│                             │  3. tool_check_market_trend   │        │
│                             │  4. tool_search_market_price  │        │
│                             │  5. tool_check_urgency        │        │
│                             │  6. tool_search_alternatives  │        │
│                             │  7. tool_analyze_cost_anomaly │        │
│                             │                             │        │
│                             │ node_conclude_diagnosis      │        │
│                             │   → 综合根因判断              │        │
│                             │   → 计算诊断置信度            │        │
│                             │   → 调用兜底方案生成           │        │
│                             │   → 写入 trace: "诊断结论"    │        │
│                             │                             │        │
│                             │  ╔══════════════════════╗   │        │
│                             │  ║ node_wait_human      ║   │        │
│                             │  ║ ← interrupt() 暂停   ║   │        │
│                             │  ║ 等待人工反馈/决策    ║   │        │
│                             │  ╚══════════════════════╝   │        │
│                             │                             │        │
│                             │ node_finalize               │        │
│                             │   → 汇总human_feedback      │        │
│                             │   → 写入 trace: "流程结束"   │        │
│                             └─────────────┬───────────────┘        │
│                                           ▼                        │
│                                         END                        │
└─────────────────────────────────────────────────────────────────────┘
```

### 分流逻辑

```
         node_triage
              │
        deviation_score
              │
     ┌────────┼────────┐
     │        │        │
   <20    20~60    ≥60
     │        │        │
     ▼        ▼        ▼
  快速通道  标准诊断  紧急升级
  (自动)   (Agent+)  (Agent+)
           人工确认   强制确认

     ─ 方案数量 ─
  1个方案   多方案    多方案+升级
```

## 六、人机交互（Human-in-the-Loop）

用户可以对分析结果做 **5 种操作**：

### 操作1：选择方案 → 进入跟进

```
POST /api/quotes/{id}/select-solution

请求:
{
  "selected_solution_id": "SOL-Q-20250603-A",
  "selected_by": "当前用户",
  "note": "目标价¥4.80，要求供应商提供成本明细"
}

响应:
- 方案标记为已采纳 (selected_solution_id)
- 状态进入 "resolution" 阶段
- 执行轨迹追加:
    ① "人工选定方案"
    ② "Agent跟进行动"
- 写入 decision_log
```

### 操作2：提交最终决策

```
POST /api/quotes/{id}/decision

请求:
{
  "decision": "accept",    // 或 reject
  "decision_by": "当前用户",
  "override_reason": "供应商已确认降价至¥4.80",
  "selected_solution_id": "SOL-Q-20250603-A"
}

响应:
- 状态: approved / rejected
- 尝试恢复 LangGraph Agent 执行 (resume_with_feedback)
```

### 操作3：注入人工反馈

```
POST /api/quotes/{id}/feedback

请求:
{
  "feedback_type": "modify",   // agree | modify | override
  "content": "供应商历史数据中有1次涨价是合理的",
  "reasoning": "那次涨价是因为原材料ABS涨价20%",
  "step_index": 3
}

用途:
- 写入 decision_log（标记具体步骤索引）
- 后续执行 Override 时自动复用此反馈作为上下文
```

### 操作4：执行 Override（4 种类型）

```
POST /api/quotes/{id}/override

类型一: 价格 Override
{
  "override_type": "price",
  "override_value": 5.50,
  "override_reason": "该供应商此前报价一直稳定在¥5.50左右",
  "modified_params": { "supplier_quote": 5.50 }
}
→ 触发重跑 → 返回 Diff 结果

类型二: 方案 Override
{
  "override_type": "solution",
  "override_value": "联系备选供应商B报价，目标对比后确定",
  "override_reason": "AI未考虑供应商B的竞争报价策略"
}
→ 记录到 decision_log，不触发重跑

类型三: 模型参数 Override
{
  "override_type": "model_param",
  "override_value": {"alpha": 0.5, "beta": 0.3, "gamma": 0.2},
  "override_reason": "历史数据充足，应提高内部数据权重"
}
→ 触发重跑

类型四: 标记 Override
{
  "override_type": "flag",
  "override_value": "误判：报价包含特殊灭菌工艺",
  "override_reason": "AI未能识别医疗级灭菌附加成本"
}
→ 标记为误判，用于模型迭代反馈
```

### 操作5：对比重跑结果

```
GET /api/quotes/{id}/compare/{compare_id}

响应 (Diff):
{
  "deviation_score": { "old": 55.0, "new": 62.1, "change": 7.1 },
  "severity_level": { "old": "警示", "new": "紧急" },
  "price_deviation": { "old": 45.2, "new": 52.3, "change": 7.1 },
  "diagnosis_conclusion": {
    "old": {"root_cause": "供应商溢价..."},
    "new": {"root_cause": "成本结构异常..."}
  },
  "solutions": {
    "old": [SOL-A, SOL-B, SOL-C],
    "new": [SOL-A, SOL-D]
  }
}
```

## 九、完整启动命令

### 环境要求

- Python 3.11+
- Node.js 18+
- Kimi API Key（AI 诊断功能必需）

### 后端

```bash
cd SMM_Agent/backend

# 安装依赖
pip install -r requirements.txt

# 配置环境变量
# 创建 backend/.env:
#   KIMI_API_KEY=sk-xxx
#   KIMI_BASE_URL=https://ai-gateway.ailab.jiuan.com/v1
#   KIMI_MODEL=kimi-k2.5

# 初始化数据库 + 迁移 JSON 数据
python -m app.db.migrate

# 生成测试数据（500物料 + 200报价 + 行情数据）
python -m app.db.seed_data --reset

# 启动服务
python run.py
# 或: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 前端

```bash
cd SMM_Agent/frontend

# 安装依赖
npm install

# 启动开发服务器
npm run dev
# → http://localhost:5173
```

### 体验流程

```
1. 访问 http://localhost:5173
   → 看到 Dashboard (工作台首页)

2. 点击「调试演示」→ /demo
   → 选择「供应商溢价诊断」
   → 观看两阶段执行动画
   → 查看分析结果

3. 点击「查看完整调试工作台」
   → /quotes/{id}/trace
   → 时间线 + DAG 双视图
   → 注入反馈 / Override / 对比重跑

4. 或直接新建分析
   → /quotes/new
   → 填写物料/供应商/报价
   → 点击「开始分析」
   → 查看完整诊断结果
```
