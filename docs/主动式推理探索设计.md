# 主动式推理探索体验设计

## 一、核心理念：从"查看报告"到"调查案件"

```
改前: 用户被动接收 AI 结论
  输入报价 → 等待 → AI 输出报告 → 用户通过/驳回 → 结束

改后: 用户主动调查 AI 推理
  输入报价 → AI 初步分析 → 用户检查每个环节 →
    ├── "这个成本项为什么偏高？" → 展开证据链
    ├── "如果我把报价改成 ¥8.00 呢？" → 实时 what-if
    ├── "我不同意这个诊断，原因如下..." → 结构化异议
    ├── "对比之前类似案例" → 历史复盘
    └── "重跑后有什么变化？" → 并列对比
```

## 二、QuoteDetail → 调查工作台

### 当前问题

```
用户看到结论后只能:
  ① 通过
  ② 驳回
  ③ Override（但不知道 Override 什么）

用户没有"中间状态"的探索空间
```

### 新设计：三段式调查工作台

```
┌──────────────────────────────────────────────────────┐
│  ── 阶段1: 概况 ──                                   │
│  结论横幅 + 3项核心指标 (同上一版)                     │
│                                                      │
│  ── 阶段2: 调查与验证 ──                             │
│                                                      │
│  🔍 证据审查                                         │
│  ┌─ 价格预测 ──────────────────────────────────┐    │
│  │  AI说合理价是¥4.65，区间¥4.20~¥5.10          │    │
│  │  [为什么是这个区间？] → 展开贝叶斯模型参数     │    │
│  │  [试试其他价格] → 弹窗输入新价格看影响        │    │
│  └──────────────────────────────────────────────┘    │
│                                                      │
│  ┌─ 成本拆解 ──────────────────────────────────┐    │
│  │  原材料偏离+222% ⚠️                         │    │
│  │  [查看交叉验证数据] → 展开 1688 市场行情     │    │
│  │  [我不认同这个基准] → 选择其他行业基准        │    │
│  └──────────────────────────────────────────────┘    │
│                                                      │
│  ┌─ 诊断推理 ──────────────────────────────────┐    │
│  │  AI认为: 供应商溢价（置信度75%）              │    │
│  │  [查看推理过程] → 展开假设-验证链            │    │
│  │  [我有不同意见] → 注入反馈，AI重新评估       │    │
│  └──────────────────────────────────────────────┘    │
│                                                      │
│  ── 阶段3: 决策 ──                                   │
│  方案选择 → 最终决策                                  │
│  (每个决策需要选择"决策依据")                         │
└──────────────────────────────────────────────────────┘
```

### 关键交互模式

#### 模式1：证据审查卡

每个证据卡片有三个状态：

```
折叠态: 标题 + 一句话摘要
  ▶ 价格预测  P50=¥4.65 · 区间¥4.20~¥5.10

展开态: 完整数据 + 操作入口
  ┌──────────────────────────────────────────────┐
  │  价格预测详情                                 │
  │                                              │
  │  供应商报价:  ¥15.00                         │
  │  贝叶斯 P50:  ¥4.65   ← AI 认为的合理价     │
  │  预测区间:    ¥4.20 ~ ¥5.10                  │
  │                                              │
  │  ┌─ 偏离计算 ──────────────────────────┐    │
  │  │  (15.00 - 4.65) / 4.65 × 100 = +222% │    │
  │  └──────────────────────────────────────┘    │
  │                                              │
  │  [🔬 查看原始数据]  [✏️ 提出异议]           │
  └──────────────────────────────────────────────┘
```

#### 模式2："What-If" 即时实验

每个关键参数旁边有一个实验入口：

```
当前报价: ¥15.00  [✏️ 试试其他价格]
                              ↓
                    ┌──────────────────────┐
                    │ 输入新价格: [____]    │
                    │                      │
                    │ 即时预估结果:         │
                    │  偏离度: 222% → 85%   │
                    │  级别:   紧急 → 警示   │
                    │                      │
                    │ [预览变化] [重跑分析]  │
                    └──────────────────────┘
```

#### 模式3：结构化异议

当用户不同意 AI 的某个判断时，不能只说"我不同意"，要选择原因：

```
[✏️ 提出异议]
         │
         ▼
┌──────────────────────────────────────┐
│ 你对什么有异议？                      │
│                                      │
│ ○ 价格预测区间不合理                  │
│ ○ 成本基准比例不合适                 │
│ ○ 供应商画像不完整                   │
│ ○ 误判了根因                         │
│ ○ 其他                               │
│                                      │
│ 你的依据：                           │
│ [_____________________________]      │
│                                      │
│ 期望的修正结果：                     │
│ [_____________________________]      │
│                                      │
│ [提交异议 → AI重新评估] [取消]       │
└──────────────────────────────────────┘
```

## 三、ExecutionTrace → 推理调试器

### 当前问题

```
时间线是平坦的日志，用户只能看不能操作
看完了还是不知道 AI 为什么那么想
```

### 关键交互模式

#### 模式1：步骤级反馈

```
在任意步骤上都可以:
  [✓ 同意] → "我认可这个判断" (增强AI置信度)
  [✗ 异议] → "这里有问题，因为..." (触发重评估)
  [↻ 从此重跑] → "从这个节点开始，我用不同的参数试试"
  
每一条反馈都成为 AI 的学习信号
```

#### 模式2：对比模式

```
┌─ 并排对比 ──────────────────────────────────────┐
│  原始分析              │  调整后分析              │
│                        │                         │
│  价格预测: ¥4.65       │  价格预测: ¥5.20        │
│  偏离度: 167分         │  偏离度: 92分           │
│  级别: 紧急            │  级别: 警示             │
│  结论: 供应商溢价      │  结论: 市场行情驱动     │
│                        │                         │
│  差异高亮:                                  │
│  ┌────────────────────────────────────────┐ │
│  │ 偏离度 ↓75 · 级别 紧急→警示 · 根因变化 │ │
│  └────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

#### 模式3：假设树

```
将诊断假设可视化为树状结构:

        ┌─ H1: 供应商溢价 P=60%
        │     ├─ 证据: 历史偏差+12%→+38% ✓
        │     └─ 证据: 同行均价 ¥11.07 ✓ 
        │         → 更新置信度: 85%
        │
 偏离模式 ──┼─ H2: 市场行情 P=25%
        │     ├─ 证据: 未查到近期行情 ✗
        │     └─ → 更新置信度: 15%
        │
        └─ H3: 数据稀疏 P=10%
              └─ 证据: 该供应商15条记录 ✓
                  → 排除
```

## 四、核心交互组件

### 4.1 EvidenceCard（证据审查卡）

```tsx
<EvidenceCard
  title="价格预测"
  summary="P50=¥4.65 · 区间 ¥4.20~¥5.10"
  status={priceDeviation > 60 ? 'anomaly' : 'normal'}
>
  {/* 展开后的详细内容 */}
  <PriceDetail data={...} />
  
  {/* 操作区 */}
  <CardActions>
    <ActionButton icon={Eye} label="查看原始数据" />
    <ActionButton icon={MessageSquare} label="提出异议" />
    <WhatIfButton param="supplier_quote" current={15.00} />
  </CardActions>
</EvidenceCard>
```

### 4.2 WhatIfPanel（即时实验）

```tsx
<WhatIfPanel
  parameters={[
    { key: 'supplier_quote', label: '报价', value: 15.00, min: 0, max: 30 },
    { key: 'alpha', label: '价格权重', value: 0.5, min: 0, max: 1, step: 0.05 },
    { key: 'beta', label: '成本权重', value: 0.3, min: 0, max: 1, step: 0.05 },
  ]}
  onPreview={(params) => recalculateDeviation(params)}
/>
```

### 4.3 StructuredFeedback（结构化异议）

```tsx
<StructuredFeedback
  target="tool_predict_price_range"
  options={[
    { id: 'data_insufficient', label: '历史数据不足' },
    { id: 'model_bias', label: '模型偏差' },
    { id: 'feature_missing', label: '缺少关键特征' },
    { id: 'other', label: '其他' },
  ]}
  onSubmit={(feedback) => handleFeedback(feedback)}
/>
```

### 4.4 ComparisonMode（并排对比）

```tsx
<ComparisonView
  left={{ label: '原始分析', quote: original }}
  right={{ label: '调整后', quote: rerun }}
  highlights={['deviation_score', 'severity_level', 'diagnosis_conclusion']}
/>
```

## 五、实现优先级

| 组件 | 复杂度 | 用户价值 | 建议 |
|------|--------|---------|------|
| `EvidenceCard` 证据审查卡 | 低 | 高 | **立即实现** |
| `WhatIfPanel` 即时实验 | 中 | 高 | **推荐实现** |
| `StructuredFeedback` | 中 | 中 | 待规划 |
| `ComparisonMode` | 低 | 高 | **立即实现**（复用现有 DiffView） |
| 推理链三栏布局 | 高 | 高 | 待规划 |
| 假设树可视化 | 高 | 中 | 待规划 |

### 本次实现的 3 个改进

1. **EvidenceCard** — 每个证据卡片增加「提出异议」和「查看原始数据」入口
2. **What-If 预览** — 报价输入旁的实时实验入口
3. **决策依据选择** — 通过/驳回时让用户选择依据
