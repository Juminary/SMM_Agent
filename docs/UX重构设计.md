# UX 重构设计

## 一、当前体验问题诊断

### 问题1：信息轰炸，没有层级

```
当前布局: 所有卡片同级展开
┌─────────────────────────────────────────────────────┐
│  KPI KPI KPI KPI KPI    ← 5个KPI指标                │
│  执行链路总览                                          │
│  价格信息  成本结构拆解  供应商画像  同行对比          │
│  市场行情  库存紧急度  相似物料  诊断过程              │
│  应对方案  AI诊断结论  人工干预记录  LLM摘要          │
│  处理流程  方案备注  最终决策                          │
└─────────────────────────────────────────────────────┘

问题: 用户不知道先看什么。所有信息优先级相同 = 没有优先级。
```

### 问题2：没有任务引导

```
用户进入页面看到的是"数据面板"而不是"待办任务"

当前: "这里有10个卡片，你自己看吧"
应该: "报价偏离 +167%，属于紧急异常。建议你：先选方案 → 再提交决策"
```

### 问题3：状态不透明

```
- 按钮可用/不可用没有明确的上下文说明
- 不知道当前在流程的哪一步
- "处理流程"面板埋在最右侧，用户可能根本找不到
```

### 问题4：动线混乱

```
新建分析流程:
  填写表单 → 点击提交 → 跳转详情 → 滚动查找决策区 → 选方案 → 提交

问题: 提交后直接跳到详情页，中间没有"分析中"的过渡状态
      用户以为页面卡住了，其实 AI 在后台跑了 2 分钟
```

## 二、设计原则

### 原则1：结论优先

```
用户关心的是"这个报价有没有问题"，不是"贝叶斯模型的P50是多少"

┌── 结论 ──────────────────────────┐
│  🔴 紧急异常 · 偏离度 167 分      │
│  供应商报价 ¥15.00 远高于 AI 预测  │
│  建议: 先选择应对方案，再提交决策   │
└──────────────────────────────────┘
       │
       ▼
  ┌── 关键证据 (3项) ─────────────┐
  │  报价 vs 预测 | 市场 | 成本   │
  └──────────────────────────────┘
       │
       ▼
  ┌── 详细证据 (可展开) ──────────┐
  │  ▶ 价格预测 / 成本拆解 / ...  │
  └──────────────────────────────┘
```

### 原则2：渐近披露

```
一屏只展示当前任务需要的信息，其余折叠

Step 1: 结论横幅 + 关键指标  (0.5秒读懂)
Step 2: 选择方案 + 决策      (核心操作区)
Step 3: 审查证据 (按需展开)
Step 4: 查看推理链 (可选深入)
```

### 原则3：一屏一动作

```
每个页面只有一个主要操作按钮，其余都是次要或辅助

Dashboard     → [新建报价分析]
NewQuote      → [开始分析]
QuoteDetail   → [选择方案] 或 [通过/驳回]
ExecutionTrace → 浏览/回放 (分析性页面，无强制操作)
```

### 原则4：状态驱动 UI

```
页面根据当前状态呈现不同视图:

空闲态 → 引导用户开始
加载态 → 显示进度，让用户知道在等什么
结果态 → 显示结论 + 建议操作
完成态 → 显示结果 + 下一步
错误态 → 明确的错误信息 + 重试
空状态 → 引导创建第一条数据
```

## 四、页面级改动

### 4.1 Dashboard → 任务启动器

```
改前: KPI面板 + 异常分布 + 最近报价 (信息堆砌)
改后: 
  - Hero区: 大号[新建报价分析]按钮 (一屏焦点)
  - 进行中的分析: 紧凑列表 (需要关注的任务)
  - 最近分析: 简洁列表 (历史记录)
  - 去掉: KPI数字、异常分布图、快捷操作
```

### 4.2 NewQuote → 三步向导

```
改前: 单页表单 + 实时分析预览
改后:
  Step 1 "填什么": 物料名称 + 供应商 + 报价 + 数量 (核心必填)
       → 底部一排模板按钮快速填充
  Step 2 "详细信息": 尺寸/精度/工艺/备注 (可选，折叠态)
  Step 3 "确认": 预览所有输入 + AI将执行的检查清单
       → 大号[开始分析]按钮
  → 顶部步骤指示器 (Step 1/3 ● ● ●)
```

### 4.3 QuoteDetail → 结论优先 + 渐进披露

```
改前: 10个卡片同时展示，决策区藏右侧
改后:
  顶部: 结论横幅 (颜色+图标+一句话诊断)
        - 🟢 正常: "报价在合理区间，建议直接通过"
        - 🟡 关注: "报价轻度偏离，建议关注"
        - 🟠 警示: "报价中度偏离，需要处理"
        - 🔴 紧急: "报价严重偏离，必须处理"
  
  中部: 决策区 (始终可见)
        - 方案选择 (如果还未选)
        - 最终决策按钮 (如果已选方案)
  
  下部: 可展开证据面板
        ▶ 价格预测 (点击展开)
        ▶ 成本结构拆解
        ▶ 诊断推理链
        ▶ 供应商画像 + 同行对比 (合并)
        ▶ 市场行情 + 库存 (合并)
  
  右侧: 去掉独立的右栏，整合到主流程中
```

### 4.4 新增：分析过渡页

```
提交分析后 → 显示进度页:
  - 动画进度条
  - 当前执行步骤 (实时更新)
  - 已完成步骤打勾
  - 预计时间
  - 完成后自动跳转到详情页
```

## 五、交互细节

### 空状态引导
- 无分析记录时: 大号插画 + "开始你的第一次报价分析"
- 无待处理时: "所有报价已处理 ✓"

### 加载反馈
- 分析过程中: 骨架屏 + 步骤动画
- 操作提交时: 按钮loading态 + 禁止重复点击

### 成功/错误反馈
- Toast 通知 (非模态，不打断流程)
- 操作完成后高亮变化的内容

### 可发现性
- 所有可点击的展开项用 ▶ 图标暗示
- 折叠项显示摘要 (如: "价格预测 ¥4.20~¥5.10")
- 决策按钮始终固定在视口内
